# 0.3.7 启动代理预认证

日期：2026-10-08。

## 问题

用户在 Chrome 启动时偶尔看到本扩展代理入口要求用户名和密码，取消后普通网页仍可使用。截图中的入口与 Chrome 保存的晴空 PAC 一致。当前新标签页由 iTab 提供。

Chrome 154 会过滤其他扩展发起的请求，包括其代理认证事件。隔离检查确认：凭据缓存为空时，另一个扩展请求收到 407，但晴空收不到认证回调；普通网页完成晴空自动认证后，另一个扩展可以复用 Chrome 缓存。现场具体触发请求尚未捕获，不能断言截图中的请求一定来自 iTab。

## 改动

- 连接、启动恢复以及切换配置后，当前配置还没有成功的会话检测记录时，自动访问既有、强制经代理的检测地址。该请求完成代理认证并建立 Chrome 凭据缓存，用户无需先打开普通网页或点击测速。
- 预认证使用既有自动检测和恢复流程，不生成手动延迟结果。正常情况下静默完成；两次检测失败后进入已有每 30 秒自动复查流程。
- 凭据读取与会话健康、分流缓存初始化分开，认证回调只等待凭据配置。
- 启动恢复后再排队执行过期订阅刷新，避免慢订阅请求挡住预认证。
- 预认证的网络等待位于配置队列之外。切换节点或断开取消旧请求；旧结果不能覆盖新配置。
- 认证挑战来自已配置但当前未启用的节点时取消该次认证，避免在断开或选线期间打开登录框。普通网站认证和其它代理仍交由其原处理方；节点凭据只提供给当前选中端点。

## 必要检查

完成 `npm run build`、`node checks/auth-startup.cjs`、`node scripts/pack.mjs`。没有执行全量、回归、冒烟或哈希检查。

Playwright 驱动实际安装的 Chrome 154.0.8037.98，使用隔离 profile、真实 0.3.7 产物、本机 TLS 代理/目标和虚构凭据。所有测试流量由本机 fixture 接收；无关 Chrome 后台请求在 fixture 中拒绝，不连接外部目标。仅隔离浏览器忽略本机自签证书错误，产品证书策略未修改。

检查通过：

1. 连接后自动处理新鲜 407，完成 HTTPS CONNECT 和检测请求。
2. 未打开普通网页、未手动测速，另一扩展请求已经能使用缓存凭据，无需提供账号密码。
3. 完整退出隔离 Chrome 后重新启动，仅重新加载扩展，不打开其 UI 或普通网页，保存的连接配置自动触发预认证；另一扩展再次请求成功。
4. 自动认证保持手动延迟为未检测。
5. 切换到第二个独立端口，使用该端口自己的虚构凭据认证。
6. 请求未完成时断开仍响应，取消请求并清除恢复 alarm；旧响应不会恢复 ON。

结果位于 `work/auth-startup-result.json`。检查所需的本机证书可通过 `python checks/incognito-cert.py` 准备，要求 Python 环境已有 cryptography。

## 证据边界

此修改减少凭据缓存为空的时间窗口。Chrome 已经发给其它扩展、并且没有交给晴空的认证挑战，无法由晴空的回调追溯处理；如果其它扩展先于预认证发出请求，仍可能出现窗口。因此不能承诺在所有启动时序下完全消除弹窗。

隔离检查验证了自动认证和缓存效果，没有捕获新的可见原生登录窗口，也没有对用户日常 Chrome 的 iTab 请求进行现场拦截。自动化重启后通过 CDP 重新加载扩展，不等同于用户已安装扩展随浏览器自然启动的完整时序。没有修改服务器或把原本应代理的请求改成直连。
