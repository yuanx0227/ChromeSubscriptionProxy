# 0.3.4 启动错误自动复核

用户反馈重开 Chrome 偶尔出现错误提示但实际可用。0.3.3 只在手动探测成功时清除致命事件提示，没有自动复核，且 worker 初始化与 onStartup 会重复设置同一 PAC。截图不能确定原始 Chrome 事件原因，本轮修复已确认的恢复处理缺口。

- Chrome 已由本扩展控制且 PAC 相同时不重复设置，减少启动和 worker 唤醒时的配置切换。
- 当前配置收到 fatal=true 事件后，先显示“正在检查代理…”，使用 Chrome alarm 在约 30 秒后复核当前节点。
- 复核沿用保留的代理检测地址，超时 12 秒。成功清除警告及徽标；失败显示“代理检测未通过，可点击测延迟重试”，不据一次检测宣称整条线路不可用。
- 自动检测自身产生的代理事件不再次安排检测，防止循环。手动检测仍保留，自动复核不写入手动延迟结果。
- 弹窗/设置页监听后台配置变化，复核成功后已打开的页面也更新状态，不覆盖正在编辑的订阅或域名文本。

必要检查：后台事件模拟覆盖相同 PAC 不重复应用、启动错误自动复核恢复、失败保留准确提示、自身错误不循环调度，并保留之前的事件顺序检查；Playwright 页面交互检查通过，构建及打包成功。没有修改服务器或日常浏览器 profile，也未声称在用户机器上重现了原始启动错误。

加载目录仍为 dist/extension，版本 0.3.4，CRX 位于 releases/qingkong-0.3.4.crx。
