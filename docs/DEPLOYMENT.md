# 服务器部署清单

日期：2026-09-27。用户已明确授权“部署并验证测试”，已按本清单执行。以下保留操作方案；现场结果及差异以 [DEPLOYMENT-RESULT.md](DEPLOYMENT-RESULT.md) 为准。

## 最终行为和变更范围

1. 保留原 VLESS/REALITY 主核心和 3x-ui，不给其增加共享 HTTP 账户，不重启主核心。
2. 新建服务账号 `chrome-proxy`，用于独立 Xray 子进程。适配/supervisor 以 root 运行，原因是必须只读面板 DB、读取 Caddy 0600 私钥、维护防火墙；systemd 限制它的写入范围。子进程显式降权且不继承附加组。
3. 安装本项目 `server/`、Python 虚拟环境到 `/opt/chrome-subscription-proxy`；配置在 `/etc/chrome-subscription-proxy/config.json`，仅 root 可读。
4. 状态在 `/var/lib/chrome-subscription-proxy`，包括永久端口注册表、桥接配置和受限 TLS 副本。注册表 0600；Xray 配置/TLS 副本 root:chrome-proxy 0640；父目录 0750。
5. 启用一个新的 `chrome-subscription-proxy.service`，其中一个 supervisor 管理独立 Xray 子进程和 `127.0.0.1:2097` 订阅服务。原订阅上游仍为 `127.0.0.1:2096`。
6. 现有 Caddy 域名内，仅把原 CLASH 路由的上游从 2096 改为 2097。路径原样转发，不能使用会剥离前缀的 `handle_path`。原 SUB、面板和其他路由保持原行为。
7. 每身份固定端口。当前六个身份预计 18443–18448，实际分配顺序以首次编译结果为准。默认保留 18443–18542（100 个历史身份槽位），不静默回收已删除用户端口。
8. 新建专属 nftables 表 `inet csp_bridge`，只对上述端口范围生效：放行已分配的活跃端口，丢弃其余端口；用户变化自动同步。现有防火墙若默认 DROP，仍需在其现有规则中允许该范围到达本服务，最终有效开放范围由新表限制。不得清空或重写原规则集。

该表只在此项目服务中使用。检测到同名非项目表时拒绝启动，不接管。服务停用会停止子进程并把保留端口范围全部阻断；它不会撤销原防火墙配置。

## 部署前的必要确认

- 当前 2097、18443–18542 是否仍可用于本方案；之前只核对过六个拟用端口，整个保留范围尚未现场核对。必要时在首次注册前缩小/调整范围。
- 原 Xray 可执行文件的真实路径和版本，与 v26.7.28 配置兼容；配置中的占位符必须替换。
- 原 Caddy CLASH 的真实匹配前缀及其转发方式；在服务器本地写入配置，不把完整订阅路径贴到日志。
- nftables 是否安装、现有 UFW/iptables/nftables 规则和供应商防火墙是否允许上述集成；没有核对前不直接套用放行命令。
- 原账户都存在对应的 `client_traffics` 记录。缺少记录、重复且不一致的 email 身份、不同来源节点无法唯一匹配时拒绝桥接。
- 不把 `server/config.example.json` 原样当成可运行配置；其中有刻意保留的占位符。

## 配置与安装顺序

1. 在服务器创建账号、上述目录和 Python 环境，安装 `server/requirements.txt`。将 systemd unit 放入 `/etc/systemd/system/`。
2. 从示例生成 0600 的真实 `config.json`，填入原 CLASH 前缀、原 Xray binary 路径。域名必须是 TLS 证书覆盖的 `bwh.yxzyl.cn`；所有用户共用域名但各自独立端口。
3. unit 的 `ReadWritePaths` 目录必须先创建。主服务只读 DB 与 Caddy 证书，写自己的 state 目录。
4. 在获批端口范围设置与现有防火墙兼容的规则，再启用新服务。每次应用配置前，服务以降权后的 Xray 执行 `run -test`；失败不启动桥接，且不会打印包含凭据的配置/诊断。
5. 新服务正常产生配置和本机订阅后，修改原 Caddy 对应路由，先用 `caddy validate` 检查，再 reload。禁止改原公网 URL、公开本机 2097、关闭 TLS 校验，或把所有用户补进全局 inline provider。
6. 对照 `active-ports.json` 核实实际开放端口，再进行下列最小验收。

Caddy 局部示意（只能融入已核实的现有域名配置，不能覆盖整个 Caddyfile）：

```caddyfile
@existing_clash path /EXISTING_PREFIX/*
handle @existing_clash {
    reverse_proxy 127.0.0.1:2097
}
```

如果域名级别已启用访问日志，需要对该订阅路由配置 `log_skip` 或等价的已安装版本支持方式，以免路径令牌进入日志。适配服务自身不记录路径、查询参数、原 UUID、代理账号或密码。

## 必须执行的最小真实验收

| 验收 | 成功标准 |
|---|---|
| 原地址导入 | 用户原 CLASH URL 返回原节点及其自己的 HTTPS 节点；其他用户账号不在其中 |
| 独立认证 | 甲的凭据不能访问乙的入口；无账号被拒绝 |
| 实际流量路径 | Chrome 请求经 HTTPS → 原 VLESS 身份；无直连 outbound |
| 切换身份 | 正常 Chrome 同一配置中切换两个入口，原面板分别记到选中账户；不能仅看相同服务器出口 IP |
| 流量归属 | 对应 `client_traffics` 增长；其他用户不被错记；不把桥接统计并入面板 |
| 停用/额度 | 使用隔离验收身份触发停用/额度，应代理请求失败，不能桥接直接出网；原有长连接处置以面板/主核心行为为准 |
| 同步 | 新建/删除/UUID 更改约一分钟内反映；插件下一次刷新获取新凭据；原核心 PID 不因桥接更新变化 |
| TLS | 公网 HTTPS 入口证书链/域名正确；续期副本更新后仅桥接进程重启 |
| 状态恢复 | 正常 Chrome 重启恢复；订阅失败保留缓存；节点移除手动重选；代理冲突提示 |

实际执行情况见部署验收记录；未覆盖的证书续期等项目在记录中单独列明。

## 同步和失败行为

每 30 秒读取同一份只读 SQLite 事务快照，最多 8 路并发读取有效订阅（每次 6 秒超时）。当前六个身份目标一分钟内同步。远超八个订阅时耗时可能增长，需重新评估周期目标。

按“原入站 ID + email + subId”保留端口，UUID 改变时轮换代理凭据；不同 owner 获得新端口。历史端口永不自动转让。注册表在公开入口前原子持久化，必须保留；丢失它可能破坏身份/端口稳定性，不能无审阅地清空重建。

只有匹配自身订阅中的 UUID、原入站端口及 VLESS/TCP/REALITY 配置才会生成入口。额外的非支持节点原样保留。原 select groups 不改写，避免改变其他客户端默认选线；Chrome 直接读取顶层 proxies。

面板不可读、某次订阅读取失败、生成配置无效、TLS 同步失败时，首版选择停止整个浏览器桥接并暂时不提供适配订阅；原 Xray 服务独立运行不受此进程影响。恢复后下一轮自动重建。一个订阅服务错误会影响其他浏览器用户，这是首版保守的可用性取舍。

## 撤回顺序

1. 把 Caddy 原 CLASH 路由恢复为原来的 2096 上游，检查后 reload。
2. 停止并禁用新服务，只终止它管理的独立桥接子进程。
3. 撤销本次在现有防火墙中追加的规则；删除本项目专用 nft 表，不碰其他规则。
4. 保留注册表，避免未来把历史端口误分配。卸载文件、证书副本或账号须按具体撤回指令执行。
5. 确认原面板、订阅、VLESS/REALITY 10443 的既有功能继续工作。
